# 领域模型与 IPC 契约

> [!summary]
> 本文定义前端、Tauri adapter、JobManager 与 local engine 之间必须共享的业务语义。目标不是固定代码结构，而是让不同子任务在不互相猜测的情况下独立实现。

## 目标

- 建立稳定、可版本化、可测试的跨层契约。
- 避免前端 DTO、后端模型和 engine 配置出现三套含义相近但不一致的结构。
- 明确同步 command、异步 event 和可重建 snapshot 的分工。
- 保持 Create Task 参数的强类型与 encoder-specific 扩展能力。

## 边界

### 本文覆盖

- 输入资源、处理选项、编码器选项、输出策略和任务控制的领域概念。
- 创建、查询、取消、清理和应用初始化所需 IPC 能力。
- 任务快照、队列快照、结果摘要和事件 envelope。
- 字段兼容、枚举演进、协议版本和序列化约束。

### 本文不覆盖

- 具体 Rust/TypeScript 类型声明和文件布局。
- 单个表单控件、表格列或视觉反馈实现。
- codec 内部参数如何影响算法。
- IPC 之外的网络协议或远程任务。

## 依赖

- [[00-integration-overview|集成层实施总览]]：提供冻结的调用链与职责边界。
- [[02-progress-error-cancellation|进度、错误与取消]]：提供任务状态、阶段、错误和取消语义。
- 前端 Create Task 需求：提供用户可表达的任务意图。
- 后端 JobManager 设计：提供队列、并发和快照能力。
- rimage library 公共类型与实际 feature 集：约束可支持的 encoder 和 operation。

## 领域分层

### 1. 用户意图层

- 描述用户选择了哪些输入、操作、编码器与输出策略。
- 允许包含 UI 合理默认值，但不包含运行时进度或 worker 分配。
- Create Task 表单提交后形成不可变请求；后续修改应产生新任务或明确的任务编辑动作。

### 2. 任务定义层

- JobManager 接受并规范化后的可执行任务定义。
- 补齐后端权威默认值、生成 ID、记录创建时间并冻结实际配置。
- 必须能够被审计和复现，不能依赖提交后变化的前端全局状态。

### 3. 执行层

- local engine 使用的强类型处理规范。
- 只包含完成一次处理所需的信息，不包含 Tauri window、event channel 或前端文案。
- encoder-specific 选项保持独立命名空间，禁止把所有参数压平到一个松散对象。

### 4. 观察层

- 任务快照、条目快照、队列统计、进度和结果摘要。
- 面向 UI 展示，但由 JobManager 生成。
- 快照需要足够完整，使 UI 在错过事件后能够恢复。

## 核心对象语义

### Create Task 请求

应表达以下概念：

- 请求契约版本。
- 一个或多个输入资源及其输入顺序。
- 通用处理选项及其明确启用状态。
- 唯一目标 encoder 及对应的 encoder-specific options。
- 输出目录、命名、覆盖、备份和元数据策略。
- 用户可选的调度提示；最终并发决策仍属于 JobManager。

约束：

- 前端不得发送 worker ID 或直接指定内部执行槽。
- 输入路径必须由后端重新校验，不信任浏览器侧扩展名判断。
- 默认值应在协议中有单一权威来源；UI 展示默认值与后端默认值需由契约测试保持一致。

### Job Snapshot

应表达以下概念：

- 稳定 job ID、创建时间和最近更新时间。
- 规范化后的任务摘要，而不是仍可变化的表单引用。
- 当前状态、当前阶段、总体进度和条目计数。
- 成功、失败、取消和跳过数量。
- 可执行控制能力，例如当前是否允许取消、清理或重试。
- 终态结果摘要和可展示的错误摘要。

### Item Snapshot

- 每个输入资源拥有独立 item ID，不能仅依赖路径。
- 能表达排队、处理中和终态，并关联输出路径与单项错误。
- 大批量任务默认按需查询或分页，避免每次进度事件携带完整列表。

### Result Summary

- 记录输入输出数量、总字节变化、耗时和处理结论。
- 文件路径与数值数据保持机器可读，不预先拼接本地化文案。
- 成功任务允许存在跳过项；是否视为部分成功需由状态模型统一定义。

## IPC 能力分组

### 应用初始化

- 查询后端能力：支持的 encoder、operation、参数范围和 feature availability。
- 获取完整队列快照：供启动、窗口重载和事件丢失后恢复。
- 查询运行配置：并发限制、平台能力和协议版本。

### 任务操作

- 创建任务：返回 JobManager 已接受的权威任务快照。
- 查询任务：按 ID 获取当前快照。
- 查询任务条目：支持分页、状态过滤和稳定排序。
- 取消任务：返回已受理的控制结果，不伪装为立即完成。
- 清理终态任务：只移除可安全清理的记录，不影响仍在运行的任务。
- 重试失败项：作为新执行意图，保留来源关联，避免原地篡改历史结果。

### 队列与执行策略

- 查询和设置允许的并发上限。
- 暂停/恢复属于 JobManager 能力；若首版不实现，契约中不得提前暴露无效按钮。
- “添加 worker”若保留，应映射为并发策略调整，而不是创建前端持有的虚拟 worker 实体。

## Command、Event 与 Snapshot 分工

| 通道 | 适合内容 | 不适合内容 |
| --- | --- | --- |
| Command | 用户意图、立即校验、操作受理、按需查询 | 长时间处理、连续进度流 |
| Event | 状态变化提示、增量进度、终态通知 | 唯一真相、完整历史、必须可靠送达的数据 |
| Snapshot | 初始化、恢复、对账、详情查询 | 高频逐像素或逐步骤广播 |

事件采用统一 envelope，至少具备：

- 协议版本与事件类型。
- job ID；条目事件还需 item ID。
- JobManager 的单调递增 revision 或等价顺序标识。
- 事件发生时间与必要 payload。

前端处理规则：

- 只接受 revision 更新的新状态。
- 发现 revision 跳跃、未知事件或解析失败时，主动重新获取 snapshot。
- event 只触发增量更新，最终展示必须可由 snapshot 独立还原。

## 兼容与演进策略

- 首次正式契约即标记版本；版本用于识别不兼容形态，不随每次字段新增递增。
- 新增可选字段必须定义缺省语义；不得通过 `null`、缺失和空字符串表达三种未文档化状态。
- 枚举跨 IPC 使用稳定字符串语义，不把内部序号当公开契约。
- 未识别 encoder、operation 或状态必须返回结构化“不支持”，不能静默降级。
- 删除或重命名字段需经过兼容窗口；内部模型可重构，但对外 DTO 由 adapter 隔离。
- capability 响应是当前构建的权威能力来源，UI 不硬编码假设所有 codec 都已编译。

## 分阶段任务

### 阶段 1：术语与状态冻结

- 定义 job、item、request、snapshot、result 和 capability。
- 对齐状态机和终态含义。
- 决定首版支持的 command 与明确不支持的控制项。

### 阶段 2：契约样例与校验矩阵

- 为每类请求、快照、事件和错误准备最小与完整样例。
- 列出必填、可选、默认、互斥、范围和 feature-gated 规则。
- 对 Create Task 各 encoder 建立独立参数组。

### 阶段 3：双端适配

- 后端将 IPC DTO 转换为 JobManager/engine 领域对象。
- 前端使用生成或集中维护的契约类型，不复制枚举字符串。
- 建立 serialization round-trip 和 capability 驱动表单测试。

### 阶段 4：恢复与兼容

- 实现 snapshot 初始化、revision 对账和未知事件恢复。
- 对旧原型 command 提供一次性迁移或直接移除，并记录破坏性变更。
- 冻结首个可发布协议版本。

## 交付物

- 跨层术语表和领域对象清单。
- command、event、snapshot、capability 的契约说明。
- Create Task 校验矩阵与 encoder 参数分组表。
- 状态/错误/事件的固定样例集。
- 前后端序列化与兼容测试。
- 旧原型接口迁移说明。

## 验收标准

- 前端无需了解 rimage 内部类型即可完整表达首版任务。
- 后端能够拒绝所有无效、矛盾或当前构建不支持的请求，并给出结构化原因。
- UI 丢失任意数量的 event 后，可仅凭 snapshot 恢复一致状态。
- capability 与 Create Task 可选项一致，禁用 feature 不会留下可提交的幽灵参数。
- 字段默认值、枚举值和状态含义在文档、前端和后端测试中一致。
- 领域模型不依赖 Tauri 类型，IPC adapter 不持有业务状态。

## 避坑点

- 不把 Rust 内部枚举序号直接当 IPC 值；重排代码会破坏兼容。
- 不用一个 `options` 字典承载所有 encoder 参数；无法可靠校验互斥和范围。
- 不让前端提交后继续通过共享 store 修改运行中的任务定义。
- 不在高频事件里反复发送完整任务树；大批量输入会造成序列化和渲染压力。
- 不假定 command 响应先于 event 到达；两者应通过 ID 和 revision 对账。
- 不把本地化文本放进错误契约；跨层传递错误码和结构化上下文。
- 不把 Windows 路径规则泛化为所有平台；路径显示、校验与内部表示需要分层。
