# 原生外壳、设置与国际化实施计划

## 1. 目标

把窗口控制、文件入口、应用设置、错误通知和国际化整理为统一的桌面应用外壳，使业务模块不再散落调用原生 API，并保证 Windows 开发版与安装版行为一致。

本模块不改变图片处理能力，重点是：

- 原生窗口操作有反馈、可恢复、不会误伤运行任务。
- 文件选择和拖放进入统一输入流程。
- 设置按作用域持久化，并以后端确认的能力为准。
- 中英日三种语言覆盖核心路径且布局稳定。

## 2. 当前状态

- 自定义标题栏已支持拖动、置顶、最小化和退出。
- 语言通过 `localStorage["language"]` 保存，默认英文。
- 拖放监听位于主页面，目录扫描和 MIME 过滤职责分散在前后端。
- Create Task 的添加按钮尚未真正打开原生文件选择。
- 原生调用缺少统一错误捕获，失败时可能表现为“没有反应”。
- 主界面仍存在硬编码英文，例如 GO、STOP、Success、Error、ClearAll、Drop here、No results。
- 置顶状态只保存在组件内，窗口实际状态与 UI 可能在异常后不同步。

## 3. 范围与依赖

### 3.1 本模块负责

- App Shell 初始化、全局错误边界和原生能力状态。
- 标题栏拖动、最小化、置顶、关闭及关闭确认。
- 文件/目录选择、拖放事件和拖放遮罩。
- 应用级设置的加载、修改、保存和失败恢复。
- 全局 Toast、命令失败提示和错误详情入口。
- 中英日资源、语言切换、格式化和翻译质量。

### 3.2 本模块不负责

- 扫描目录后的最终格式判断和任务创建；见 [[01-create-task-form]]。
- 队列暂停、取消和退出策略的业务执行；见 [[02-task-queue-and-workers]]。
- 图片处理错误的生成，只负责呈现后端提供的结构化信息。

### 3.3 依赖

- 后端提供应用设置、CPU/concurrency 能力、队列活跃状态和安全退出命令。
- Tauri 权限覆盖窗口控制、选择文件/目录、事件监听和 process 退出。
- 产品侧确认设置项作用域：全局默认、当前会话或单次任务覆盖。

## 4. 文件选择与拖放

### 4.1 统一入口

以下入口应汇入同一 Inputs 候选管线：

- 主界面添加文件。
- 主界面添加目录。
- 窗口拖放文件或目录。
- Create Task 内继续添加。

入口只收集用户选择，不在前端承诺文件可处理。目录展开、路径规范化、软链接/权限错误和格式能力由后端统一处理。

### 4.2 拖放体验

- 只有拖入窗口且不被其他 modal 阻挡时显示遮罩。
- 遮罩明确接受文件和目录，支持 Escape/离开窗口取消。
- drop 后立刻进入 Create Task 输入区，并显示正在检查或后端拒绝结果。
- 大批量路径不能阻塞窗口；需要可取消或至少有进度反馈。
- 重复路径、同名文件、无权限目录和损坏路径都必须可解释。

### 4.3 安全边界

- 不申请不必要的全盘读写权限。
- 不让前端以 MIME 扩展名过滤作为最终结论。
- 不在 UI 中拼接或猜测输出路径。
- 不因单个路径错误让整个拖放流程静默失败。

## 5. 标题栏与窗口生命周期

### 5.1 标题栏

- 可拖动区域不能覆盖交互控件。
- 置顶、最小化和关闭按钮应有 tooltip、键盘焦点和翻译文本。
- 置顶图标显示实际窗口状态；命令失败时恢复并提示。
- 窗口无系统装饰时，应保留清晰的关闭目标和足够点击区域。

### 5.2 关闭行为

关闭前先读取真实队列状态：

- 无活动任务：直接安全退出。
- 有排队或运行任务：展示后端支持的选项，例如等待完成、暂停后退出、取消并退出。
- 退出命令失败：窗口保持打开并说明原因。
- 不允许仅调用 process exit 绕过后端清理、备份回滚或状态落盘。

具体可用动作以后端生命周期设计为准，前端不自行承诺“后台继续处理”。

## 6. 设置

### 6.1 设置分类

| 分类 | 设置 | 说明 |
| --- | --- | --- |
| General | 语言 | 默认英文，支持中英日 |
| Window | 始终置顶 | 与窗口真实状态同步 |
| Input | 默认递归扫描输入目录 | 只影响新建表单默认值 |
| Processing | 默认 concurrency | 以后端允许范围为准 |
| Output | 默认输出策略 | 只作为新建任务默认值，不回写已创建任务 |

第一阶段只交付已有产品需求或后端已支持的设置；主题、自动更新等不在没有明确需求时扩张。

### 6.2 设置状态原则

- 设置值、保存状态和后端实际生效值分开表达。
- 立即生效项失败时回滚 UI；需重启项明确标记。
- 修改默认值只影响未来表单，不改变已创建任务。
- 设置存储损坏时回退安全默认值，并允许用户恢复默认。
- 不把运行队列快照保存到设置存储。

## 7. 国际化

### 7.1 语言范围

- 英文作为默认和 fallback。
- 简体中文、日语覆盖全部用户可见核心文案。
- 枚举值、状态、错误类别、按钮、tooltip、空状态和确认框均进入翻译资源。
- 编码器品牌名和行业术语可保留英文，但说明文字需要翻译。

### 7.2 资源组织

按功能域组织 key，避免一个扁平文件持续膨胀：

- app/window/settings
- createTask/inputs/output/operations
- codecs/mozjpeg/jpeg/avif/oxipng/webp
- queue/tasks/workers
- errors/validation/common

key 表达语义，不把完整英文句子当 key，也不依赖组件路径命名。

### 7.3 文案规则

- 同一概念统一术语，例如 Workers、任务、队列、保留目录结构。
- 明确区分“输入目录递归扫描”和“输出保留目录结构”。
- STOP 必须替换为真实动作名称，例如 Pause 或 Cancel All。
- 错误消息优先展示用户可处理信息，技术详情作为展开内容。
- 数字、百分比、文件大小、日期和耗时按当前 locale 格式化。

### 7.4 布局与无障碍

- 使用最长语言文案检查按钮、tab、表格和 Dialog，不通过固定宽度截断关键操作。
- tooltip 不能是获取信息的唯一方式。
- 图标按钮必须有可访问名称。
- 状态颜色必须配合文本或图标。

## 8. 全局通知与错误呈现

- 字段错误留在表单附近，不用 Toast 代替。
- 一次性命令成功或失败可使用 Toast，但应说明对象和结果。
- 任务处理错误保留在任务详情，不因 Toast 消失而丢失。
- 原生 API 不可用、权限不足和后端断连使用持续状态提示。
- 未知错误提供复制诊断信息入口，但避免直接暴露敏感完整路径。
- 相同高频错误应合并，防止事件风暴产生大量 Toast。

## 9. 交付物

- 集中的原生窗口/文件/设置 adapter。
- 标题栏真实状态同步和安全关闭流程。
- 文件、目录选择与拖放统一入口。
- 设置页面或设置面板、默认值与持久化规则。
- 中英日按功能域组织的翻译资源。
- 全局 Toast、持续错误状态和错误详情约定。
- Windows dev、debug build、安装版的原生行为验收记录。

## 10. 阶段任务

### Phase NS1：原生调用收口

- 收拢窗口、文件、设置和退出调用。
- 统一 pending、错误归一化和用户提示。
- 建立原生能力不可用时的降级界面。

### Phase NS2：文件入口

- 完成添加文件、添加目录和拖放统一流程。
- 接入后端路径检查和部分拒绝反馈。
- 覆盖批量输入、无权限路径和重复路径。

### Phase NS3：窗口与设置

- 完成置顶真实状态、最小化和安全关闭。
- 完成第一阶段设置项、持久化和恢复默认。
- 与队列模块联调活动任务退出策略。

### Phase NS4：国际化与无障碍

- 清除核心流程硬编码文案。
- 重组中英日资源并补 fallback/缺失检查。
- 完成长文案、键盘、焦点和状态可访问性验收。

## 11. 验收标准

- 原生操作失败均有明确反馈，不出现静默无响应。
- 添加文件、添加目录和拖放都进入相同 Create Task 输入状态。
- 单个无效路径不会导致整批输入丢失。
- 置顶按钮与窗口实际状态一致，失败时不会显示错误状态。
- 有活动任务时关闭窗口会进入明确的安全退出流程。
- 设置重启后恢复；损坏或不兼容值能回退默认。
- 中英日核心路径无缺失 key、明显硬编码或关键控件溢出。
- 切换语言不会重置 Create Task 草稿或队列状态。
- 图标按钮、状态和 Dialog 焦点满足基本键盘与屏幕阅读器要求。

## 12. 避坑点

- 不要让页面组件到处直接调用 Tauri API，错误策略会失控。
- 不要用 `exit(0)` 绕过 JobManager 的关闭与清理流程。
- 不要把置顶 UI 状态当作窗口真实状态。
- 不要在前端同时扫描目录、读取 stat、做 MIME 判定，再让后端重复一遍。
- 不要在 Modal 打开时让拖放遮罩抢占交互。
- 不要把翻译 key 继续堆成不可维护的扁平列表。
- 不要把 GO/STOP、Success、Error 等主流程文案硬编码在组件中。
- 不要让语言切换重新挂载并清空业务草稿。
- 不要把默认设置修改追溯应用到已经创建的任务。
- 不要在错误消息中默认展示完整用户路径或内部堆栈。

## 13. 可交给子 Agent 的工作包

| 工作包 | 任务范围 | 依赖 | 交付物 | 完成条件 |
| --- | --- | --- | --- | --- |
| NS-A Native adapter | 窗口、文件、设置、退出调用收口 | 后端命令与权限 | 原生调用边界 | 组件无散落调用 |
| NS-B File entry | 文件/目录选择、拖放和拒绝反馈 | NS-A、Create Task Inputs | 统一输入入口 | 批量与部分失败可用 |
| NS-C Window lifecycle | 置顶、最小化、安全关闭 | queue activity 契约 | 标题栏与关闭流程 | 活动任务不被误杀 |
| NS-D Settings | 分类、加载、保存、回滚、默认值 | settings 契约 | 设置界面和状态 | 重启与损坏恢复通过 |
| NS-E i18n | 资源重组、硬编码清理、术语表 | 各功能文案清单 | 中英日完整资源 | 缺失检查通过 |
| NS-F Accessibility | 键盘、焦点、可访问名称、长文案 | NS-B 至 NS-E | 验收记录和修正 | 核心流程可键盘完成 |

NS-A 是 NS-B/NS-C/NS-D 的共同前置；NS-E 可在功能文案冻结后并行，NS-F 持续跟进而非末尾一次处理。
