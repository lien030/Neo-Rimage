# 任务队列与 Workers 实施计划

## 1. 目标

建立由后端 JobManager 驱动的任务队列界面。前端通过完整快照和事件显示任务、进度、结果及执行 slot，不再自行维护权威任务或 worker 状态。

目标体验：

- 应用启动即可恢复真实队列。
- 创建任务后立即看到后端返回的 Idle/Queued 任务。
- 启动、暂停、取消、重试和清理都有明确结果。
- 每个任务可看到状态、进度、当前阶段、输出结果或错误原因。
- Workers 区域反映真实并发 slot，而不是手动创建线程的假象。

## 2. 当前问题

| 项目 | 当前行为 | 风险 |
| --- | --- | --- |
| task store | 前端持有 `taskList` 并可直接清空 | 与后端状态漂移，运行任务可能从界面消失 |
| GO/STOP | 只切换本地 `running` | 按钮文案与真实处理无关 |
| worker 添加 | 前端生成 id，命令成功后 push 本地数组 | 页面刷新或事件丢失后不一致 |
| worker 删除 | pop 最后一个前端 worker | 可能删除错误 slot，且无法表达执行中的缩容 |
| worker 状态 | Idle/Busy/Done 由本地对象显示 | 当前任务与完成状态不可信 |
| task status | 仅有 Idle/Processing/Done/Error | 缺少 queued、paused、cancelled 等运行语义 |
| task actions | Options 列无真实动作 | 无法检查、取消、重试或移除 |
| clear all | 同时清空本地 cache 和 list | 不会影响后端队列，造成幽灵任务 |

## 3. 范围

### 3.1 本模块负责

- 应用启动时拉取队列完整快照。
- 订阅任务、队列和进度事件，并更新只读快照 store。
- 呈现任务表格、状态、进度、结果和错误详情。
- 提供启动、暂停、取消、重试、移除、清理已完成项等操作。
- 呈现真实 concurrency 配置和后端执行 slot。
- 处理命令进行中、失败、事件丢失和重同步。

### 3.2 本模块不负责

- 创建或修改图片处理配置；由 [[01-create-task-form]] 负责。
- 生成 task id、推断任务状态或直接改变运行结果。
- 创建操作系统线程或决定 codec 内部线程数。
- 在任务完成前计算输出大小、压缩率或最终路径。

## 4. 权威状态与同步模型

### 4.1 后端为唯一数据源

以下字段只能由后端快照或事件写入：

- queue mode：idle、running、paused、stopping 等。
- task 状态、进度、当前阶段、错误、结果和时间信息。
- worker/slot 数量、忙闲状态和当前任务。
- concurrency 上限及其实际生效状态。
- 可执行动作，例如任务能否取消、重试或移除。

前端可以保存筛选、排序、展开行、选中项和 loading，但不能直接把任务从 Queued 改成 Processing。

### 4.2 初始化顺序

启动同步需要覆盖“拉取快照期间已有事件发生”的竞态。前后端需约定以下任一种可靠机制：

- 订阅事件后拉取带 revision 的快照，再丢弃旧事件；或
- 拉取快照并从其 revision 继续订阅；或
- 检测到 revision 间隙后主动重拉。

前端必须有全量重同步入口，不能假定事件永不丢失。

### 4.3 命令结果

- 操作按钮进入局部 pending，避免重复触发。
- 命令成功后以返回快照或随后事件确认结果。
- 命令失败不应改变权威 store，只显示错误并恢复按钮。
- 超时或结果不确定时触发完整快照查询，不做猜测。

## 5. 任务状态与动作

最终状态名以后端契约为准，但至少要覆盖：

| 状态类别 | UI 语义 | 常用动作 |
| --- | --- | --- |
| Queued/Idle | 等待执行 | 取消、移除、查看配置 |
| Processing | 正在处理 | 取消、查看进度 |
| Paused | 队列暂停或任务等待恢复 | 恢复、取消 |
| Done | 成功完成 | 打开输出位置、查看结果、移除 |
| Error | 处理失败 | 查看错误、重试、移除 |
| Cancelled | 已取消 | 重试、移除 |

状态灯只能作为辅助，必须同时提供文本或图标含义，不能依赖颜色表达全部信息。

### 5.1 任务表格

建议按信息优先级呈现：

- 状态和进度。
- 输入文件名与完整路径提示。
- 输出格式/关键 preset。
- 当前阶段或结果摘要。
- 操作菜单。

详细配置、错误链、输入/输出大小、耗时和输出路径放入行详情或侧栏，避免主表过宽。

### 5.2 批量操作

- 清理动作应区分“清理已完成”“清理失败/取消”“取消全部等待项”。
- 运行中的任务不得被纯前端隐藏；需要先经过后端取消或明确保留在快照中。
- 批量动作需展示影响数量和不可执行项，避免一个通用 Clear All 覆盖所有语义。

## 6. Queue 控制

### 6.1 启动与暂停

- GO 替换为与后端 queue mode 一致的 Start/Resume。
- STOP 的语义必须拆清：暂停取新任务、取消运行任务、还是停止并清空。默认建议使用 Pause，只阻止新任务开始；取消应是独立危险动作。
- 队列为空、后端未就绪或正在转换状态时，按钮应正确禁用并解释原因。

### 6.2 Concurrency

- concurrency 表示同时运行的任务 slot 数，不等同于 codec 内部线程数。
- 调整 concurrency 通过后端命令确认，前端不自行增删 worker 对象。
- 缩容时要展示“将在当前任务完成后生效”或后端定义的实际语义。
- 上限和推荐值以后端 CPU/内存预算为准，不硬编码为浏览器可见 CPU 数。

## 7. Workers 视图

Workers 更准确的产品含义是“执行 slot 监视器”。若保留 Workers 名称，应在文案或帮助中说明：

- 每个卡片来自后端快照。
- Idle 表示可接任务，Busy 表示正在处理，Draining 表示缩容后不再接新任务。
- 卡片显示当前任务、阶段和简要进度，不展示前端生成的随机 id。
- `+`/`-` 应成为 concurrency 调整入口，或替换为数值设置；操作成功前不改变卡片数量。
- Done 是任务状态，不适合作为长期 worker 状态；slot 完成任务后应回到 Idle。

如果后端决定不公开 slot 细节，可将此区域简化为“并发使用量 + 当前处理任务”，不要模拟不存在的 worker 生命周期。

## 8. 错误与恢复

- 命令错误：靠近操作按钮提示，必要时提供重试。
- 任务错误：保留任务行，展示结构化类别、用户可读消息和技术详情入口。
- 后端不可用：冻结危险操作，显示连接状态，并周期性或手动重同步。
- 事件解析失败：记录诊断信息并重拉快照，不让页面崩溃。
- 应用重启：后端仍在或已恢复的任务以快照为准；前端不得从本地 storage 恢复旧运行状态。
- 退出中的任务：由后端定义暂停、取消或等待策略，前端只展示确认信息。

## 9. 交付物

- 只读 queue/task/slot 快照 store。
- 启动同步、事件订阅、revision 检测和全量重同步机制。
- 任务表格、详情和状态/进度显示。
- Start/Resume、Pause、Cancel、Retry、Remove、Clear Finished 流程。
- concurrency 控件和后端驱动的 Workers 视图。
- 错误详情、连接状态和恢复体验。
- 队列/事件契约测试和关键流程验收用例。

## 10. 阶段任务

### Phase Q1：只读同步

- 冻结快照和事件契约。
- 完成启动拉取、事件订阅、revision 处理和重同步。
- 用后端快照渲染任务表和 Workers，移除本地权威状态。

### Phase Q2：基础控制

- 接入 Start/Resume、Pause 和 concurrency。
- 明确按钮禁用、pending 和失败恢复。
- 将当前 GO/STOP 与 worker `+`/`-` 替换为真实命令语义。

### Phase Q3：任务动作

- 完成取消、重试、移除和清理已完成项。
- 增加任务详情、错误和结果入口。
- 处理批量动作中的部分成功。

### Phase Q4：可靠性与体验

- 完成断连、事件间隙、重启恢复和高频进度节流。
- 对大任务列表做渲染性能和可用性优化。
- 完成退出处理中任务的确认体验。

## 11. 验收标准

- 应用启动后任务、队列和 slot 状态与后端完整快照一致。
- 刷新前端或切换语言不会改变任何任务运行事实。
- 丢失事件或 revision 不连续时可自动恢复到正确快照。
- Start/Pause/Cancel/Retry/Remove 均有 pending、成功和失败路径。
- 前端不会在命令确认前自行改变任务状态或 worker 数量。
- 运行中任务不能被纯本地 Clear All 隐藏。
- worker 完成任务后回到后端定义的 Idle，而不是停留在 Done。
- 高并发进度事件不会造成界面明显卡顿或任务顺序混乱。
- 错误任务保留可诊断信息，且可按后端能力重试。

## 12. 避坑点

- 不要同时维护后端 task 列表和一份独立可写前端 task 列表。
- 不要使用 optimistic update 推断 Processing、Done、Cancelled。
- 不要把 Pause 和 Cancel All 放在同一个模糊的 STOP 按钮下。
- 不要把 worker slot 当作永久线程身份；执行器可能动态调度。
- 不要让每个进度事件触发整页重渲染，应有合并/节流策略。
- 不要只靠颜色区分状态，需兼顾色觉和屏幕阅读器。
- 不要在移除任务时丢掉仍需查看的错误或输出信息而无确认。
- 不要假定命令响应一定早于事件，store 更新要可去重且幂等。
- 不要把前端本地 storage 当作运行队列恢复来源。
- 不要把 concurrency 与单 codec 内部线程配置混为一谈。

## 13. 可交给子 Agent 的工作包

| 工作包 | 任务范围 | 依赖 | 交付物 | 完成条件 |
| --- | --- | --- | --- | --- |
| Q-A 快照同步 | 初始化、订阅、revision、重同步 | 后端 snapshot/event 契约 | 只读同步 controller | 事件丢失可恢复 |
| Q-B 任务表格 | 状态、进度、摘要、详情、空状态 | Q-A | 后端驱动任务视图 | 无本地伪造状态 |
| Q-C Queue 控制 | Start/Resume、Pause、禁用和 pending | queue commands | 控制区 | 操作结果与后端一致 |
| Q-D Task actions | Cancel、Retry、Remove、Clear Finished | task commands、Q-A | 行操作和批量操作 | 覆盖部分失败 |
| Q-E Workers/Concurrency | slot 监视、并发调整、缩容提示 | slot/concurrency 契约 | Workers 新视图 | 不生成本地 worker id |
| Q-F 恢复与性能 | 断连、重启、高频进度、大列表 | Q-A 至 Q-E | 恢复策略和性能验收 | 压力场景稳定 |

Q-A 是其余工作包的公共前置；Q-B、Q-C、Q-E 可在 Q-A 接口稳定后并行。
