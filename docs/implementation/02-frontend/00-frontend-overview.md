# 前端实施总览

## 1. 目标

把当前可操作的界面原型升级为 rimage GUI 的可靠客户端。前端负责配置编辑、用户操作、状态呈现和原生窗口交互；任务执行、任务状态、并发状态和文件处理结果均以后端为准。

前端最终需要形成四条完整闭环：

1. 选择或拖入文件 → 编辑配置 → 校验 → 创建任务。
2. 获取队列快照 → 启动、暂停、取消、重试 → 持续呈现后端状态。
3. 接收进度与结果事件 → 更新任务、worker slot 和通知。
4. 管理窗口、语言和应用级设置 → 在重启后恢复用户偏好。

详细模块见：

- [[01-create-task-form|Create Task 表单计划]]
- [[02-task-queue-and-workers|任务队列与 Workers 计划]]
- [[03-native-shell-settings-i18n|原生外壳、设置与国际化计划]]
- [[04-frontend-quality-plan|前端质量计划]]

## 2. 当前状态判断

当前代码已经具备布局、shadcn 基础组件、拖放入口、任务表格、worker 面板、Create Task Dialog、MozJPEG 局部控件和中英日资源，可继续沿用视觉方向。

但当前实现仍属于交互原型，关键问题如下：

| 领域 | 当前状态 | 影响 |
| --- | --- | --- |
| Create Task | 没有确认/提交动作，编码器 tab 不完整，多个控件未写回 | 可见配置无法形成真实任务 |
| 表单状态 | 表单配置生命周期不稳定，编辑值允许被重新初始化 | 用户输入可能丢失或与界面不一致 |
| 任务状态 | `taskList` 由前端持有，尚未由后端快照驱动 | 运行状态、错误和完成结果不可信 |
| Workers | 前端自行添加/移除展示项 | UI worker 与真实执行资源可能漂移 |
| GO/STOP | 只切换本地布尔值 | 不会真正控制队列 |
| 文件发现 | 前端读取文件信息、按 MIME 过滤，后端又扫描目录 | 能力判断和错误处理分散 |
| 协议模型 | 表单、IPC、任务显示共用相近类型并依赖数字枚举 | 易出现字段丢失和协议静默错位 |
| 错误反馈 | 原生调用失败缺乏统一呈现 | 用户会看到“按钮没反应” |

更完整的背景和参数清单见 [[../../rimage-core-integration-review|rimage 核心集成设计评审]]。

## 3. 前端职责边界

### 3.1 前端负责

- 呈现输入文件候选、配置表单、队列、进度、结果和错误。
- 保存尚未提交的表单草稿和纯界面状态。
- 将通过前端基础校验的配置提交给 Tauri adapter。
- 在启动时获取完整后端快照，并订阅后续事件。
- 将窗口、语言、提示和无障碍行为做成一致体验。
- 对后端拒绝、超时、断连和版本不兼容给出可恢复的界面。

### 3.2 前端不负责

- 判断某种文件是否最终可被 rimage 解码。
- 生成权威 task id、worker id 或任务状态。
- 推断任务完成、失败或取消。
- 自行计算输出路径冲突、备份结果和压缩结果。
- 直接管理操作系统线程或把“worker 卡片数量”当作线程事实。
- 在本地乐观完成会改变处理结果的业务动作。

## 4. 状态分层原则

前端状态必须分为三类，不再通过一个全局 store 混合承载。

### 4.1 表单草稿状态

用于 Create Task 编辑，允许不完整和暂时无效。它只在用户提交成功前存在，包含编码器参数、预处理顺序、输出选项和输入候选的选择状态。

约束：

- 表单重渲染不能重置草稿。
- 关闭、取消、重新打开时采用明确的保留或丢弃规则。
- 草稿不能直接成为任务表中的运行任务。

### 4.2 界面状态

用于 Dialog 开关、当前 tab、过滤条件、选中行、拖放遮罩、语言菜单和临时提示。这些状态可以由前端独立持有，但不能改变后端任务事实。

### 4.3 后端快照状态

任务列表、队列运行状态、worker slot、进度、输出结果和错误由后端返回。前端只缓存最近快照并渲染，不自行伪造状态转换。

约束：

- 应用启动先拉取完整快照，再消费增量事件。
- 事件丢失、页面重载或检测到版本间隙时，重新拉取完整快照。
- Create Task 成功后使用后端返回的任务快照，不在前端预生成任务。
- 所有任务动作以操作结果或新快照确认，失败时恢复可操作状态并提示原因。

## 5. 前端分层

| 层级 | 职责 | 不应包含 |
| --- | --- | --- |
| App Shell | 页面布局、窗口区域、全局错误边界、初始化流程 | 编码器配置细节、任务业务规则 |
| Feature | Create Task、Queue、Workers、Settings 等业务界面 | 原生 API 的散落调用 |
| Store / Controller | 管理草稿、界面状态、后端快照同步和命令状态 | 图片处理实现、线程管理 |
| IPC Adapter | 请求/响应转换、事件订阅、统一错误归一化 | 视觉组件和文案 |
| Domain Model | 前端可理解的表单值、请求类型和只读快照类型 | React 组件状态和 Tauri 细节 |
| UI / i18n | 复用组件、设计 token、翻译和无障碍约定 | 任务状态来源判断 |

表单值、创建任务请求和任务快照必须是三种独立模型：

- 表单值允许未填写完整。
- 创建任务请求必须通过校验，并与后端协议一一对应。
- 任务快照是只读运行事实，不能被表单直接修改。

## 6. 依赖与前置条件

- 后端提供稳定的任务命令、队列命令、快照查询和事件契约。
- 后端明确任务状态机、错误结构、并发语义和事件版本策略。
- rimage engine 能返回格式能力、校验错误、进度和处理结果。
- 产品侧确认第一阶段支持的编码器和参数范围；未支持项必须隐藏或明确禁用。
- 原生权限允许拖放、文件/目录选择、窗口控制和设置持久化。

前端可以先基于冻结的 mock 契约开发，但不得自行发明最终状态含义；契约发生变化时要集中修改 IPC adapter，而非逐组件修补。

## 7. 总体交付物

- 可闭环的 Create Task：输入、配置、校验、提交、错误保留和成功回写。
- 后端驱动的任务表格、队列控制和 worker slot 视图。
- 集中的 Tauri 命令与事件适配层。
- 清晰拆分的表单、界面和后端快照状态。
- 原生窗口、拖放、设置和中英日国际化闭环。
- 前端自动化检查、契约测试、关键流程测试和手工验收清单。
- 对未支持功能的可见性策略，避免出现“控件可见但无效”。

## 8. 阶段任务

### Phase F0：冻结前后端契约

- 确认创建任务请求、任务快照、队列快照和错误结构。
- 确认 task/queue 事件类型、事件顺序和全量重同步策略。
- 确认第一阶段编码器、预处理和输出选项范围。
- 建立协议字段与 i18n 文案清单。

### Phase F1：整理前端骨架与状态边界

- 拆分 App Shell、功能模块、store/controller 和 IPC adapter。
- 将表单草稿、界面状态、后端快照状态分离。
- 建立全局加载、错误、Toast 和不可用状态约定。
- 保持现有外观可用，不在本阶段扩张视觉重设计。

### Phase F2：完成 Create Task 闭环

- 按 [[01-create-task-form]] 完成输入、参数、验证和提交。
- 先交付 General、Output、Resize、MozJPEG，再扩展其余编码器。
- 所有可见控件必须能进入最终请求；未实现项不得假装可用。

### Phase F3：接入队列与实时状态

- 按 [[02-task-queue-and-workers]] 完成初始化快照、事件同步和队列动作。
- 用后端状态替换本地 GO/STOP、task status 和 worker status。
- 增加取消、重试、清理和错误详情。

### Phase F4：原生体验和产品化

- 按 [[03-native-shell-settings-i18n]] 完成窗口行为、拖放、设置和翻译一致性。
- 按 [[04-frontend-quality-plan]] 完成自动化、性能、无障碍和发布前验收。

## 9. 验收标准

- Create Task 中每个可见选项都能进入已验证请求，并由后端返回任务快照。
- 表单取消或失败不会污染队列，提交成功不会遗留幽灵草稿。
- 前端不持有权威任务状态；刷新界面后可从后端恢复真实队列。
- GO、暂停、取消、重试、清理和并发调整均以真实后端结果为准。
- worker 面板展示的是后端执行 slot，而不是前端自行维护的数组。
- 原生命令失败均有可理解反馈，不再出现无提示的“点击没反应”。
- 中英日三种语言在核心流程中无缺失 key、硬编码主文案或明显布局溢出。
- 核心流程通过 [[04-frontend-quality-plan]] 定义的自动化与手工验收。

## 10. 避坑点

- 不要让表单配置、创建请求和任务快照复用同一个类型。
- 不要继续使用数字枚举作为 IPC 协议；界面排序变化不应改变协议语义。
- 不要在 React render 周期中创建新的默认表单对象。
- 不要在前端生成 worker/task 业务 id 后假定命令成功。
- 不要把输入目录递归扫描与输出目录结构保留都命名为 `recursive`。
- 不要用文件名删除输入候选；同名不同路径必须可独立处理。
- 不要用 MIME 扩展名判断代替后端的真实格式能力检查。
- 不要先收到增量事件再忽略初始化快照；必须处理启动竞态和事件丢失。
- 不要为了“立即响应”而乐观标记 Processing、Done 或 Cancelled。
- 不要一次性补齐所有 codec UI 后再接提交链；先完成纵向闭环。

## 11. 可交给子 Agent 的工作包

| 工作包 | 任务范围 | 输入 | 交付物 | 完成条件 |
| --- | --- | --- | --- | --- |
| FE-A 契约适配 | 建立命令、事件、错误和快照的统一前端边界 | 冻结的后端协议 | IPC adapter、协议类型、mock 契约 | 功能组件不直接调用散落的原生 API |
| FE-B 状态重构 | 分离草稿、界面状态、后端快照状态 | FE-A 契约 | store/controller 结构与迁移说明 | task/worker 状态只能由快照同步 |
| FE-C Create Task | 实现 [[01-create-task-form]] | FE-A、后端创建任务命令 | 完整表单闭环 | 可创建真实任务且失败保留草稿 |
| FE-D Queue/Workers | 实现 [[02-task-queue-and-workers]] | FE-A、后端队列能力 | 队列表、控制区、worker slot 视图 | 重启后与后端状态一致 |
| FE-E Native/i18n | 实现 [[03-native-shell-settings-i18n]] | 原生权限和设置契约 | 窗口、拖放、设置、翻译闭环 | 三语言和原生行为通过验收 |
| FE-F Quality | 实现 [[04-frontend-quality-plan]] | FE-C 至 FE-E | 测试、检查、验收记录 | 阻断级用例全部通过 |

并行建议：FE-A 先冻结接口；FE-B 可与后端联调准备并行；FE-C、FE-D、FE-E 在 FE-A 之后可并行；FE-F 从 F1 开始持续介入，而不是最后补测试。
