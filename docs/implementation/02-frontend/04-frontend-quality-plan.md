# 前端质量计划

## 1. 目标

建立能阻止“控件看似可用但没有进入处理链”“前后端状态漂移”“开发版可用但安装版失效”的质量体系。质量验证围绕真实用户闭环和协议边界展开，而不是只检查组件能否渲染。

重点保障：

- Create Task 每个可见参数都能进入请求。
- 后端始终是 task/queue/worker 权威状态来源。
- 原生命令失败有反馈且界面可恢复。
- 中英日、键盘操作和长列表场景可用。
- Windows dev、debug build、安装版行为一致。

## 2. 质量门禁

每个前端工作包合并前至少满足：

- 类型检查、lint 和生产构建通过。
- 新增用户行为有对应测试或验收记录。
- 新增协议字段具备契约样例和错误样例。
- 新增可见文案具备中英日 key 或明确的品牌名豁免。
- 新增原生调用覆盖成功、拒绝和不可用路径。
- 不新增可见但不会影响最终请求/命令的“假控件”。

发布候选额外要求：

- Tauri dev、debug build 和安装版关键流程全部通过。
- 后端快照重同步、应用重启和退出活动任务通过。
- rimage 支持格式的前后端契约矩阵无漂移。

## 3. 测试分层

### 3.1 静态检查

- TypeScript 严格类型检查。
- lint 覆盖 React hooks、未处理 Promise、无效依赖和不可达分支。
- 生产构建检查别名、资源、动态导入和包体警告。
- i18n key 完整性与未使用 key 报告。
- 协议类型禁止用 UI 数字枚举直接表达编码器或任务状态。

### 3.2 领域与状态测试

覆盖纯前端规则，不依赖真实 Tauri：

- 表单默认值、dirty、reset 和编码器切换保留。
- 数值范围、依赖项、冲突项和请求转换。
- 输入候选按路径去重、同名文件独立移除。
- 快照事件去重、乱序、revision 间隙和全量重同步。
- 命令 pending、失败恢复和重复点击保护。
- i18n fallback、格式化和设置损坏回退。

### 3.3 组件与功能测试

- Create Task 打开、编辑、校验、提交、部分成功和失败保留。
- Encoder tab 和 Operations 顺序交互。
- TaskTable 的状态、进度、详情、错误和动作可用性。
- Queue 控件随真实 mode 正确启用/禁用。
- Workers 只渲染后端 slot，调整并发失败时不提前改变数量。
- 标题栏、设置、Toast、确认框和焦点管理。

### 3.4 IPC 契约测试

使用冻结样例验证：

- 创建请求与后端字段、tag、可选值和默认值一致。
- TaskSnapshot、QueueSnapshot、WorkerSlotSnapshot 可向前兼容地解析。
- 结构化字段错误能映射到表单控件。
- 未知状态或新增字段不会让整个页面崩溃；应降级展示并记录诊断。
- 事件重复、命令响应早于/晚于事件时，最终 store 一致。

### 3.5 Tauri 集成与桌面 E2E

在真实桌面窗口验证：

- 文件选择、目录选择、拖放和权限拒绝。
- Create Task → 后端任务快照 → Start → Progress → Done/Error。
- Pause/Resume、Cancel、Retry、Clear Finished 和 concurrency 调整。
- 最小化、置顶、关闭活动任务和重启恢复。
- 语言切换、设置持久化和安装版资源加载。

浏览器 localhost 只能用于纯 UI/mocked contract 测试，不能作为原生能力验收结论。

### 3.6 手工探索与视觉验收

- 中英日逐页检查长文案、截断、tooltip 和术语一致性。
- 键盘完成 Create Task 和主要队列动作。
- 1000+ 输入候选与任务行的滚动、筛选和进度更新。
- Windows 缩放比例、窗口边缘、透明背景和自定义标题栏点击区域。
- 错误信息是否可操作，是否存在“按钮没反应”。

## 4. 关键测试矩阵

### 4.1 Create Task

| 场景 | 预期 |
| --- | --- |
| 无输入提交 | 阻止提交并定位 Inputs |
| 同名不同路径 | 两项独立存在，可分别移除 |
| 重复路径 | 去重或明确提示，不重复创建 |
| 切换编码器再返回 | 各编码器草稿按规则保留 |
| 非法质量/尺寸 | 字段级错误，无法提交 |
| lossless 与冲突选项 | 显示跨字段错误 |
| 后端部分接受 | 成功任务进入队列，失败输入保留 |
| 后端不可用 | 草稿保留，显示可重试错误 |
| 快速双击 Create | 只产生一次有效请求 |
| 切换语言 | 草稿和当前 tab 不重置 |

### 4.2 Queue 与 Workers

| 场景 | 预期 |
| --- | --- |
| 初始化时已有任务 | 完整恢复任务和 slot |
| 快照拉取期间有事件 | 最终 revision 一致 |
| 重复/乱序事件 | 不回退任务状态 |
| Start/Pause 失败 | UI 不伪造 queue mode |
| 运行中取消 | 等后端确认后显示 Cancelled |
| concurrency 缩小 | 按后端语义延后生效并提示 |
| 事件断流后恢复 | 自动重拉快照 |
| Clear Finished | 只清理允许清理的任务 |
| 高频进度 | 页面响应正常，无严重抖动 |

### 4.3 Native/i18n

| 场景 | 预期 |
| --- | --- |
| 拖入文件与目录混合 | 进入同一候选流程并展示部分错误 |
| 无权限目录 | 其他合法输入不丢失 |
| 置顶命令失败 | 图标恢复实际状态并提示 |
| 活动任务时关闭 | 展示安全退出选项 |
| 设置数据损坏 | 回退默认且应用可启动 |
| 翻译缺失 | 使用英文 fallback 并被检查报告捕获 |
| 150%/200% 缩放 | 核心操作不被遮挡 |

## 5. 非功能质量指标

### 5.1 性能

- Dialog 打开、tab 切换和常规输入保持即时响应。
- 进度事件采用合并策略，避免高频更新触发全表重渲染。
- 大列表采用适合的数据呈现方式，文件候选和任务行不会一次性造成明显冻结。
- 主线程不执行目录遍历、图片格式探测或大文件读取。

### 5.2 稳定性

- 未处理 Promise rejection 和 React error boundary 异常均可被发现。
- 单个任务或路径失败不导致整个应用白屏。
- 未知协议字段可忽略，未知关键状态可降级并请求重同步。
- 所有事件订阅在组件/应用生命周期结束时正确释放。

### 5.3 可访问性

- 核心流程可用键盘完成，焦点顺序合理。
- Dialog 打开/关闭、错误定位和确认框焦点符合预期。
- 图标按钮有名称，状态不只依赖颜色。
- 输入说明、错误和单位与对应控件建立清晰关系。

### 5.4 可诊断性

- 命令、事件和快照错误有统一类别与用户提示。
- 支持复制脱敏诊断信息，包括应用版本、协议版本和错误码。
- 开发日志能定位请求、事件 revision 和重同步原因，但不默认记录敏感路径。

## 6. 交付物

- 前端测试目录与分层约定。
- Create Task、Queue/Workers、Native/i18n 的关键自动化用例。
- IPC 契约 fixtures 和兼容性用例。
- Windows dev/debug/install 三环境验收清单。
- 中英日、键盘、缩放和大列表手工测试记录。
- 已知限制、豁免项和发布阻断问题列表。

## 7. 阶段任务

### Phase QA0：测试基础与契约 fixtures

- 建立静态检查、测试运行和报告入口。
- 固定请求、快照、事件和错误样例。
- 建立 i18n key 完整性检查。

### Phase QA1：Create Task 质量门禁

- 覆盖草稿生命周期、参数校验、请求转换和提交状态。
- 建立“每个可见控件影响最终请求”的参数映射验收。
- 覆盖部分成功和后端拒绝。

### Phase QA2：队列同步与竞态

- 覆盖初始化竞态、重复/乱序事件、命令与事件顺序。
- 覆盖重同步、重启恢复和高频进度。
- 验证前端没有权威状态写入口。

### Phase QA3：桌面与发布验收

- 完成原生文件入口、窗口、设置和退出场景。
- 在 dev、debug build、安装版重复关键闭环。
- 完成长列表、语言、键盘和 Windows 缩放测试。

## 8. 验收标准

- 所有阻断级静态检查、自动化用例和桌面关键路径通过。
- Create Task 不存在可见但不进入请求的控件。
- 队列与 worker 状态可通过重启和断流恢复，最终与后端一致。
- 原生命令失败、权限错误和协议错误均可见且可恢复。
- 三语言核心流程完成，缺失 key 检查为零。
- 1000+ 条目及高频进度场景无不可接受卡顿。
- dev 成功但安装版失败的差异均有修复或明确阻断发布。
- 已知限制写入发布说明，未实现参数不会被误认为可用。

## 9. 避坑点

- 不要只测浏览器 mock 后就宣称 Tauri 功能完成。
- 不要用快照测试替代所有行为断言，关键是状态与请求是否正确。
- 不要依赖固定延时测试异步事件，应等待明确状态或 revision。
- 不要只覆盖成功路径；权限、取消、部分成功和后端拒绝是核心路径。
- 不要在测试中复制一份不同于后端的协议定义。
- 不要把高频进度全部录成脆弱的 UI 细节断言。
- 不要忽略 event unlisten 和组件重挂载造成的重复订阅。
- 不要将完整本地路径、堆栈或用户文件名写入公开测试报告。
- 不要把“生产构建通过”等同于“安装版原生能力可用”。
- 不要等功能全部完成才开始质量工作；测试应随契约和模块同步建立。
